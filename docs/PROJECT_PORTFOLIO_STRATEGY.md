# AI Project Portfolio Strategy

## Recommended identity

Use this identity across the website, CV, LinkedIn, and GitHub:

> Applied AI / Machine Learning Researcher with PhD-level scientific R&D expertise

This keeps the portfolio open to broad AI roles while preserving the advantage of polymer chemistry, materials science, and experimental research.

## Portfolio objective

The GitHub portfolio should prove three things:

1. You can build applied AI systems beyond chemistry and materials science.
2. You can work on computer vision and deployable machine-learning workflows.
3. You can use scientific R&D experience as a high-value differentiator for AI-for-science roles.

## Priority projects

### 1. AI Research Assistant with RAG

Career signal: general AI, LLM applications, retrieval, evaluation, API design, and deployment.

Minimum evidence to add:

- Document ingestion pipeline.
- Chunking and retrieval method.
- Citation-grounded answers.
- Retrieval evaluation table.
- FastAPI endpoint.
- Streamlit or simple web demo.
- Docker setup.
- Clear README with limitations.

This is the most important project for showing that the portfolio is not limited to chemistry.

### 2. Real-Time Computer Vision Tracking System

Career signal: computer vision engineering, object detection, tracking, and real-time model workflows.

Minimum evidence to add:

- YOLO-based detection pipeline.
- Tracking workflow using Deep SORT or a similar tracker.
- Example input and output.
- FPS benchmark.
- Detection/tracking metrics.
- Demo video or screenshots.
- Responsible-use note.

This project should be positioned for broad AI/ML and computer-vision roles.

### 3. Scientific AI case study

Career signal: AI-for-science, materials informatics, experimental design, and research-grade ML.

Choose one of these to upgrade first:

- `Mxene-database`
- `glycopolymer-ml-platform`
- `polyloop-bo`
- `lis-battery-research`

Minimum evidence to add:

- Data schema.
- Reproducible notebook or script.
- Baseline model.
- Error analysis.
- Feature importance or interpretation.
- Practical next-experiment recommendation.
- README written for both AI reviewers and scientific reviewers.

## Repository README structure

Use this structure for important repositories:

```text
# Project Title

## One-line summary

## Problem

## Why this matters

## Dataset or input data

## Method

## Results

## How to run

## Repository structure

## Limitations

## Next steps

## Career signal
```

## Website project card rule

Do not add a project to the top of the website only because it exists. Add it when it has evidence.

Strong project evidence includes:

- Screenshot or demo.
- Clear setup instructions.
- Metrics.
- Reproducible workflow.
- Short explanation of why the project matters.

## Recommended order for job applications

For general AI or ML engineer applications, show:

1. AI Research Assistant with RAG.
2. Real-Time Computer Vision Tracking System.
3. One scientific AI project as a differentiator.

For scientific AI or materials informatics applications, show:

1. One upgraded scientific AI project.
2. PolyLoop Bayesian Optimization.
3. AI Research Assistant with RAG.

For research software or AI product roles, show:

1. Researcher Agenda.
2. AI Research Assistant with RAG.
3. MXene or glycopolymer platform.

## MSc year execution plan

Before starting the MSc:

- Clean the GitHub profile.
- Pin the strongest repositories.
- Add the new GitHub projects page to the main website navigation.
- Make one repository fully recruiter-ready.

During the first MSc term:

- Build or upgrade the RAG project.
- Publish one deployed demo.
- Add evaluation metrics to all visible AI repositories.

During the second MSc term:

- Use coursework and dissertation work to strengthen the broad AI identity.
- Convert the dissertation or strongest coursework into a polished public repository.
- Apply broadly to ML engineer, AI engineer, research engineer, computer vision, data scientist, and scientific AI roles.

## Final positioning sentence

Use this sentence in applications and profiles:

> I build applied AI and machine-learning systems for computer vision, scientific data, and R&D workflows, combining software engineering with PhD-level experimental research experience.
